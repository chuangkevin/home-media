# 橫向版面品質驗收

目標為 Awwwards、Webby Awards、FWA 等級的設計與操作成熟度；這是品質願景，不代表獎項認證。完成與否依實際瀏覽器測試，不以主觀「已達得獎」宣稱替代證據。

## 驗收條件
- 手機低高度橫向與平板寬橫向使用不同資訊架構；以 CSS 可用寬高判斷，不依硬體解析度／UA。
- 手機播放器不得壓縮主要內容至不可操作；播放、前後曲、進度及必要功能不遭截斷。
- 寬平板：真實內容與播放器分欄，合理限制文字行長，封面／歌名／控制建立明確層級，避免空泛裝飾。
- 導覽、焦點狀態與觸控目標清楚；不以縮小所有元件掩蓋版面問題。
- 長中英文曲名、無封面、無歌曲、載入與錯誤狀態皆可理解。
- 無水平溢位、非預期重疊、底部文字截斷；內容可捲動且播放器不遮擋。
- 保留安全區、動態可視高度，回到直向／切頁不重新掛載 audio。
- 尊重 prefers-reduced-motion，不加假播放狀態或虛构歌曲。

## 自行測試矩陣
透過 ego-lite TaskSpace，對本機實作讀取實際後端資料；尺寸為 CSS viewport 模擬，不等於真機 Safari 驗收。
- 手機橫向：852×393、852×300、852×260（瀏覽器列佔用後）。
- 平板寬橫向：1920×720、1920×600。
- 一般平板：1024×768。
- 手機直向：393×852。
- 必測互動：首頁／播放清單／設定、播放控制可見性、視窗 resize 後 audio 身分保留。

## 本次執行結果
- 建置成功；103 項單元測試通過，0 項失敗。
- ego-lite 8 個實際 viewport 測試通過（含額外 667×300 小橫向）；歌曲資料與音訊取自實際後端。
- 全部尺寸：無水平溢位、播放器／導覽按鈕沒有超出 viewport、按鈕觸控區不小於 44×44 CSS px。
- 在歌曲持續播放中切換全部尺寸，兩個 audio DOM 節點保持相同，實際播放時間持續前進。
- 852×300 第二輪把導覽移到頂列、播放器由 105 px 收至 97 px，主要捲動區由 97 px 增為 154 px；第三輪移除重複視覺標題並把最近播放卡改為精簡橫排，初始畫面可辨識歌曲。
- 寬平板播放器獨立位於右側 400 px 欄，1920×720 主區與播放器不重疊；主區可獨立捲動。
- 已實際操作歌曲播放／暫停、音量設定彈出面板、首頁／播放清單／設定導覽。未操作投射或修改設定／收藏。
- QA 腳本：`frontend/tests/ego/landscape-qa.js`，需指定現有 ego TaskSpace。圖片與結果產物：`/tmp/home-media-*.png`、`/tmp/home-media-ego-matrix.json`。
- 原有依賴 npm audit 有 34 個弱點（27 高、6 中、1 低）；本次沒有做可能破壞相容性的依賴升級。建置亦保留原有大型分塊警告。

## 限制
Chromium 尺寸模擬不能替代 iPhone Safari 的安全區、背景音訊與真機觸控測試。若未真機驗證，不宣稱已完成該項。
