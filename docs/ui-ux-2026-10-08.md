# Home Media 桌機與手機 UI／UX 改善紀錄

日期：2026-10-08。使用者在基準評估後，追加授權優化全站排版，涵蓋桌機與手機。本輪修改前端介面與必要的操作狀態；使用者最後授權正常commit／push與既有CI/CD；未操作真實媒體資料，實際發佈狀態見Git記錄與本輪回報。

## 設計方向

以「家庭聆聽室」為主題：深墨、暖琥珀與暖白，讓曲名、封面、播放狀態和下一個動作優先。桌機便於瀏覽與管理待播；手機便於單手播放、閱讀歌詞及返回瀏覽。沉浸效果保留為主動選擇，不以增加動畫取代易用性。

- 正文 14–16px、輔助文字至少 12px；統一間距、深淺主題色彩與可見焦點。
- 主要觸控目標以 44px 為產品目標；圖示操作補上名稱，手勢提供可見替代操作。
- 桌機使用較密集的曲目列與導覽；窄螢幕採單欄、可捲動分頁及可開關待播面板。
- 設定先呈現使用偏好，再提供快取、封鎖與進階管理；推薦快取時間顯示小時，API 仍保留毫秒。
- 尊重減少動態偏好；載入、空資料、查無結果、失敗與取消分別呈現。

Awwwards、Webby Awards、FWA 作為設計、功能與整體體驗的參考，沒有客觀保證得獎的方法。本輪不宣稱已達獎項評審標準。

## 關鍵行為與後續維護規則

| 範圍 | 已實作／覆核的行為 |
|---|---|
| 搜尋 | 使用 `/search?q=` 保存已提交關鍵字；輸入草稿保留於 SearchBar。App 統一管理請求取消與過時回應，清除會同步清結果及 URL，保留播放參數。搜尋中仍可輸入、取消或重試；中文組字 Enter 不應送出搜尋。 |
| 搜尋結果 | 桌機採清楚曲目列，主要操作持續可見；分類僅保留真實的「曲目／依頻道」。加入待播的成功／重複提示由 App 統一負責。 |
| 待播 | `addToQueue` 加入播放器實際使用的 `playlist` 尾端，依 `videoId` 去重，不更換目前或 pending 曲目。`playNow` 換歌清除插入點後方舊推薦，是既定產品行為，不在本輪改寫。 |
| 我的播放清單 | 編輯／刪除目標與選單 anchor 分離；建立與修改失敗保留輸入，操作有 pending／錯誤狀態。加入歌單的回應必須符合歌曲與請求世代，避免 A 的晚到回應污染 B；保留逐曲已快取標示。 |
| 播放與歌詞 | 播放按鈕、收藏與開啟歌詞各有獨立操作區。歌詞首次延遲掛載不得清除 AudioPlayer 已載好的歌詞；AudioPlayer 保持共享音訊與歌詞生命週期的主要負責元件。收合校準、換模式或關閉畫面會取消未套用校準。 |
| 主題與設定 | 儲存成功後才發布 `themeChanged`，ThemeProvider 更新深／淺主題。實際 `/admin` 使用 AdminSettings；未掛載的 SettingsPage 也整理版面，但不視為正式路由驗收。 |
| 其他介面 | 首頁、紀錄、電臺、投射及相關對話框統一文字層級、間距、窄螢幕配置與可理解的狀態。 |

重新整理不自動續播，以及音訊是影片模式唯一音源等既有產品／播放規則仍保留。不得以純排版工作為由改動它們。

## 最後整合覆核

- 搜尋503後同詞鍵盤重試成功；建議選取→Tab清除→Enter不誤送搜尋。
- 建立清單dialog焦點保持圈內；Escape返回建立按鈕。設定分頁支援ArrowRight＋Enter。
- Cast使用draft選取，取消不改作用中目標；停止讀最新targets。Radio使用獨立加入訂閱，等待成功才關窗，10秒逾時回報；取消使舊重連失效；加入失敗不誤關DJ原台。
- Radio協定無request ID：舊請求永不回覆後同台重試仍存在保守忽略的限制，可能需重連；須後端echo request ID才能完整解決。未改後端。
- 播放全部guard涵蓋seek與restart意圖；一般timeupdate及完成seek清除不誤失效。手動歌詞scroll也遵守reduceMotion。
- 清單／設定／搜尋新增17組寬度量測無body橫溢；短高度截圖仍需等viewport同步後補驗，不能僅據量測算控制可達。
- ego-lite遇Mac鎖定及原生控制逾時，最終版仍未通過；200%縮放、VoiceOver、真機及跨裝置仍待驗。
